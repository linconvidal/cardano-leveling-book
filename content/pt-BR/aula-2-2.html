Objetivos
  1. Transformar bytes em folhas e combinar hashes até uma raiz.
  2. Montar uma prova mínima para um item entre quatro.
  3. Reparar um verificador que confunde a ordem esquerda/direita.
Antes de começar

Você precisa calcular hashes de bytes e entender por que a referência esperada deve vir de fora do material apresentado. Retome a Aula 2.1 para essa segunda distinção.

Pergunta-guia

Como conferir o evento B sem receber também os arquivos A, C e D?

1. Quatro arquivos, um compromisso

Um serviço fecha um lote com quatro arquivos de eventos, chamados A, B, C e D. O destinatário de B quer verificar que recebeu os bytes incluídos naquele lote. Entregar todos os arquivos funcionaria, mas aumentaria o tráfego e daria acesso a conteúdo que ele não solicitou.

Uma árvore Merkle combina hashes em níveis. Cada arquivo produz uma folha. Dois hashes adjacentes produzem um hash pai, e o processo continua até sobrar a raiz, também chamada root. Uma raiz SHA-256 tem 32 bytes, mesmo quando resume muitos arquivos. Isso não comprime os arquivos de forma recuperável: a raiz não permite reconstruí-los.

A ordem do lote faz parte do desenho. A ocupa o índice 0; B, o índice 1; C, o índice 2; D, o índice 3. O serviço preserva essa ordem e a receita de cálculo junto dos arquivos.

2. A receita vem antes da árvore

O exemplo usa quatro folhas. Os arquivos são textos exatos codificados em UTF-8, sem quebra de linha no final. H significa SHA-256; || significa concatenar bytes, não suas representações hexadecimais.

  • Folha: H(0x00 || dados).
  • Nó interno: H(0x01 || hash_esquerdo || hash_direito).

Os prefixos 0x00 e 0x01 distinguem uma folha de um nó interno. A folha depende dos bytes do arquivo. Sua posição é dada pelo caminho na árvore. Cada nó interno combina dois digests binários de 32 bytes, mantendo a ordem esquerda/direita.

Ordenar os digests por valor ou concatenar seus textos hexadecimais mudaria a receita. Quem constrói e quem verifica a árvore precisam usar as mesmas regras.

3. Calcule a raiz e abra um caminho

Execute o código. As funções retornam digests binários; .hex() aparece somente na exibição. A prova de B contém dois pares: lado do irmão e hash desse irmão. O caminho é percorrido de baixo para cima.

import hashlib

def folha(dados):
    return hashlib.sha256(b"\x00" + dados).digest()

def no(esquerdo, direito):
    return hashlib.sha256(b"\x01" + esquerdo + direito).digest()

arquivos = [texto.encode("utf-8") for texto in [
    "T-0141|criado", "T-0142|revisão",
    "T-0143|criado", "T-0144|correção",
]]
A, B, C, D = [folha(dados) for dados in arquivos]
raiz_publicada = no(no(A, B), no(C, D))
prova_B = [("E", A), ("D", no(C, D))]

recalculada = folha(arquivos[1])
for lado, irmao in prova_B:
    recalculada = (no(irmao, recalculada) if lado == "E"
                  else no(recalculada, irmao))
print("raiz:", raiz_publicada.hex())
print("inclusão:", recalculada == raiz_publicada)

B_alterado = folha(arquivos[1] + b"!")
print("arquivo alterado:", no(no(A, B_alterado), no(C, D))
      == raiz_publicada)
print("bytes de hashes na prova:", sum(len(h) for _, h in prova_B))

A saída mostra inclusão True, arquivo alterado False e 64 bytes de hashes na prova. O pacote ainda precisa levar o arquivo B, os lados e a localização da raiz. Se a consulta especifica um índice, o caminho também precisa corresponder a essa posição. “64 bytes” não é o tamanho de uma transação nem de todo o pacote.

Experimente trocar o primeiro lado da prova, de ("E", A) para ("D", A), mantendo a raiz publicada. A comparação falha. Se também trocar a raiz esperada, deixará de testar o compromisso anterior. Na aplicação, obtenha a raiz da publicação já conferida, não de um campo substituível no pacote do remetente.

4. Repare a orientação

Atividade: o irmão pode estar à esquerda

Este verificador usa o irmão à direita em todos os passos. Ele funciona para A, mas rejeita B. Repare o cálculo dentro do laço para respeitar E e D. Preserve as checagens do índice, do número de irmãos e do lado esperado. Execute para observar a falha e use Validar solução para testar outros arquivos, posições e adulterações.

A checagem do caminho já está pronta: em uma posição par, o irmão fica à direita; em uma posição ímpar, à esquerda. A divisão inteira por dois encontra a posição do pai no nível seguinte.

import hashlib

def folha(dados):
    return hashlib.sha256(b"\x00" + dados).digest()

def no(esquerdo, direito):
    return hashlib.sha256(b"\x01" + esquerdo + direito).digest()

def verificar_inclusao(indice, dados, prova, raiz):
    if not 0 <= indice < 4 or len(prova) != 2:
        return False
    atual = folha(dados)
    posicao = indice
    for lado, irmao in prova:
        lado_esperado = "E" if posicao % 2 else "D"
        if lado != lado_esperado:
            return False
        atual = no(atual, irmao)
        posicao //= 2
    return atual == raiz

arquivos = [b"A", b"B", b"C", b"D"]
A, B, C, D = [folha(d) for d in arquivos]
raiz = no(no(A, B), no(C, D))
prova = [("E", A), ("D", no(C, D))]
print("B incluído:", verificar_inclusao(1, b"B", prova, raiz))
Conferir resposta

Para E, use no(irmao, atual); para D, use no(atual, irmao). B precisa primeiro de LA à esquerda e depois de N(C,D) à direita. D exige irmãos à esquerda nos dois níveis. Por isso, testar somente A esconderia o defeito.

O verificador mantém a raiz fixa. Se uma comparação falhar, obtenha o arquivo original e confira a receita, o índice e a prova antes de atribuir a divergência a uma adulteração.

5. O que cresce e o que permanece fora da prova

Em uma árvore binária completa com 1.024 folhas, cada caminho tem dez níveis. Bastam dez irmãos, ou 320 bytes de hashes SHA-256, em vez dos outros 1.023 arquivos. O número de irmãos cresce como o logaritmo do número de folhas, enquanto construir a árvore ainda exige processar o lote.

Esta aula fixa quatro folhas para não esconder uma decisão de formato. Para lotes de tamanho arbitrário, a construção precisa definir a forma da árvore, o tratamento de níveis ímpares e o compromisso com a quantidade. Duplicar a última folha e separar subárvores de tamanhos diferentes são convenções distintas. Uma prova de inclusão também não é uma prova de que um log novo preservou todo o antigo. Logs crescentes podem usar provas de consistência específicas; isso exige outra receita.

A inclusão confirma que aqueles bytes, naquela posição, recompõem a raiz esperada. Ela não revela arquivos ausentes da captura nem comprova que o resultado de B é verdadeiro. Também não oferece sigilo automático: hashes irmãos de dados previsíveis podem permitir tentativas. Trataremos dessa exposição na Aula 2.4.

O que aprendemos

  • Folhas e nós internos têm receitas diferentes, com bytes e ordem explícitos.
  • A prova de B contém LA e N(C,D), com seus lados, sem exigir os outros arquivos.
  • Alterar arquivo, posição, irmão ou orientação invalida a comparação contra a mesma raiz.
  • A raiz compromete o lote; disponibilidade, completude da captura e sigilo exigem controles adicionais.
