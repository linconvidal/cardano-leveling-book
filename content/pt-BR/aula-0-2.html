Objetivos
  1. Calcular o SHA-256 de uma mensagem codificada em UTF-8.
  2. Comparar hashes e explicar o efeito de uma alteração na mensagem.
  3. Reconhecer os limites dessa comparação, incluindo colisões e a origem da referência.
Antes de começar

Para acompanhar esta aula, você precisa saber converter texto em bytes UTF-8 e reconhecer a representação hexadecimal, como fizemos na Aula 0.1.

Pergunta-guia

O que a comparação de hashes permite concluir sobre os dados?

1. Referências baseadas no conteúdo

Programas podem precisar reconhecer conteúdos repetidos ou detectar alterações nos dados. Uma forma de apoiar essas tarefas é calcular uma referência a partir dos próprios bytes do conteúdo, em vez de depender apenas de nomes ou identificadores atribuídos a ele.

Uma função hash realiza esse cálculo. Ela transforma uma sequência de bytes em um valor de tamanho fixo, chamado hash.

Usaremos SHA-256, uma função hash criptográfica. Seu hash tem 256 bits, ou 32 bytes, que podem ser escritos com 64 caracteres hexadecimais.

Para observar o cálculo, use a mensagem falha de comunicação. O exemplo troca apenas f por F e mostra cada mensagem acompanhada de seu hash.

import hashlib

mensagem_original = "falha de comunicação"
mensagem_alterada = "Falha de comunicação"

mensagem_original_em_bytes = mensagem_original.encode("utf-8")
mensagem_alterada_em_bytes = mensagem_alterada.encode("utf-8")
hash_original = hashlib.sha256(mensagem_original_em_bytes).hexdigest()
hash_alterado = hashlib.sha256(mensagem_alterada_em_bytes).hexdigest()

print(mensagem_original, hash_original, sep="\t")
print(mensagem_alterada, hash_alterado, sep="\t")

A função hashlib.sha256 calcula o hash dos bytes, e hexdigest() escreve esse resultado em hexadecimal. A saída mostra dois hashes diferentes, ambos com 64 caracteres. Experimente outra alteração em mensagem_alterada e execute novamente.

Se você repetir o cálculo sem alterar as mensagens, os hashes se repetirão. Com os mesmos bytes e o mesmo algoritmo, o resultado é sempre o mesmo. Essa propriedade é chamada determinismo.

No par observado, uma pequena alteração na entrada mudou grande parte do hash. Esse comportamento é chamado de efeito avalanche.

2. O que a comparação permite concluir

Usando o mesmo algoritmo, hashes diferentes demonstram que os bytes são diferentes. O hash não aponta o caractere modificado, não mede a semelhança entre os conteúdos e não informa se a alteração foi autorizada. Para localizar uma diferença, é preciso comparar os conteúdos.

Quando os hashes coincidem

Duas entradas diferentes podem produzir o mesmo hash. Essa coincidência é chamada de colisão. Por isso, hashes iguais não são uma garantia matemática de bytes iguais.

Colisões existem porque há mais entradas possíveis do que hashes de 256 bits. Uma função hash criptográfica segura, como o SHA-256, é projetada para tornar impraticável encontrá-las. Na prática, a igualdade dos hashes é tratada como forte evidência de igualdade dos bytes.

3. A referência corresponde a quais bytes?

Um hash é uma referência aos bytes usados no cálculo. Se o objetivo é conferir uma cópia exata, preservar apenas os campos e valores de um arquivo não basta.

Conferir um registro de teste

Considere um equipamento que gera um arquivo JSON com o resultado de um teste. Antes de ser usado como evidência em uma auditoria, esse arquivo passa por uma aplicação que importa e reexporta seus dados.

O equipamento calcula o SHA-256 do arquivo original, antes da reexportação. O auditor calcula o SHA-256 da versão recebida e compara os resultados. Uma nova escrita pode preservar os campos e valores e ainda produzir um hash diferente, porque os bytes mudaram. Essa conferência testa a preservação dos bytes, não apenas dos dados lidos. É uma verificação de integridade.

4. Preservar a referência

Para detectar mudanças em relação a uma versão anterior, é preciso ter uma referência preservada dessa versão. Se alguém substituir tanto o conteúdo quanto o hash guardado, a comparação poderá coincidir sem revelar a substituição.

Por isso, importa saber de onde veio o hash de referência e como ele foi protegido. O cálculo, sozinho, não identifica quem produziu o conteúdo: qualquer pessoa com os bytes pode calcular o mesmo hash.

5. Hash não é sigilo

Um hash não é uma codificação reversível como a base64. Não há uma operação de decodificação que recupere o conteúdo original a partir dele. Isso, porém, não impede testar possibilidades.

Se você souber que um texto é uma das duas mensagens do exemplo, poderá calcular os dois hashes e descobrir qual corresponde ao hash observado. Não foi necessário inverter o cálculo, apenas comparar resultados. Publicar um hash pode, portanto, revelar informação sobre um conteúdo previsível.

Atividade: compare antes de descartar

A alternativa C é a correta. O hash ajuda a encontrar possíveis cópias; a comparação direta confirma se todos os bytes são iguais antes de descartar uma delas. Outro hash criptográfico seguro pode reduzir o risco de coincidência, mas não substitui a comparação exata exigida neste caso.

O que aprendemos

  • Um hash é calculado a partir dos bytes. Com a mesma entrada e o mesmo algoritmo, o resultado se repete.
  • Hashes diferentes indicam bytes diferentes. Hashes iguais são forte evidência de igualdade, mas colisões são possíveis.
  • Uma verificação de integridade depende de saber quais bytes foram usados e de preservar a referência.
  • Hash não identifica o autor nem protege conteúdos previsíveis contra tentativas de adivinhação.
