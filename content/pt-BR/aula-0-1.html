Pergunta-guia

O que precisa ser igual para que dois arquivos sejam cópias exatas?

1. O registro e o arquivo

Registros digitais ajudam a documentar o que foi feito. O resultado de um teste, por exemplo, pode ser apresentado como evidência em uma auditoria. Para avaliar essa evidência, precisamos considerar também de onde o registro veio e o que aconteceu com ele até chegar às nossas mãos.

O auditor recebe esse registro em um arquivo JSON gerado por um equipamento. Antes de chegar às suas mãos, porém, o arquivo passou por outra aplicação, que importou os dados e gerou uma nova exportação. Ela pode ter preservado todos os valores e ainda assim mudado a ordem dos campos e os espaços. O auditor precisa distinguir uma cópia exata do arquivo original de uma nova representação dos mesmos dados.

Suponha que o equipamento tenha gerado este registro em JSON, um formato de texto que organiza os dados em campos e valores:

{
  "registro": "T-0142",
  "equipamento": "EQ-17",
  "instante": "2026-09-10T14:30:00-03:00",
  "resultado": "falha de comunicação"
}

Para recuperar esses campos, a aplicação lê uma sequência de bytes gravada no arquivo. Cada byte reúne oito bits, que podem valer 0 ou 1, permitindo 256 valores diferentes. Uma codificação define como o texto é escrito nessa sequência. Tanto os valores do registro quanto as aspas, os espaços e as quebras de linha precisam ser codificados.

Em Python, o tipo str representa texto Unicode. Unicode atribui códigos numéricos aos caracteres: e recebe 101, e é recebe 233. Esses identificadores são chamados de pontos de código. UTF-8 define como representá-los em bytes. A operação encode("utf-8") produz esses bytes; decode("utf-8") recupera o texto.

dados = "é".encode("utf-8")
print(dados)
print(dados.decode("utf-8"))

Um caractere pode ocupar mais de um byte. A palavra café, por exemplo, tem quatro caracteres, mas ocupa cinco bytes em UTF-8: o é ocupa dois. Por isso, contar letras e espaços na tela não é o mesmo que medir o tamanho do arquivo.

2. Hexadecimal e base64

Para examinar os bytes do arquivo, podemos escrevê-los em hexadecimal: dois dígitos por byte, usando 0-9 e a-f. Os cinco bytes de café ficam 63 61 66 c3 a9. Os pares c3 a9 correspondem ao é.

Base64 também permite transportar bytes em campos de texto. Nessa representação, os mesmos cinco bytes ficam Y2Fmw6k=. Decodificar o hexadecimal 636166c3a9 ou essa base64 recupera a mesma sequência. Nenhuma das duas formas impede a leitura nem verifica se o conteúdo foi alterado.

import base64

dados = "café".encode("utf-8")
hexadecimal = dados.hex()
em_base64 = base64.b64encode(dados).decode("utf-8")

print(hexadecimal, bytes.fromhex(hexadecimal).decode("utf-8"), sep="\t")
print(em_base64, base64.b64decode(em_base64).decode("utf-8"), sep="\t")

3. Os mesmos dados, bytes diferentes

Na importação do registro, a aplicação recupera os campos e valores do JSON. Ao exportá-los, produz um novo texto, que pode ter outra formatação. Essa transformação é uma forma de serialização.

Os acentos também podem ter representações diferentes. Unicode permite escrever é como um único ponto de código ou como e seguido de um acento agudo combinante. As duas formas podem parecer iguais na tela e produzir bytes diferentes. A normalização Unicode permite convertê-las para uma forma comum.

Uma reexportação pode mudar apenas a formatação ou também alterar os valores registrados. O arquivo recebido, sozinho, não revela o que mudou. Para conferir sua preservação, o auditor precisa de uma referência do registro original.

Atividade 1: interprete a comparação

O arquivo reexportado tem o mesmo tamanho em bytes do original. O auditor também confirmou que os dois JSONs contêm os mesmos campos e valores.

Qual alteração poderia passar despercebida nessas duas conferências?

Conferir resposta

Trocar a ordem dos campos mantém o tamanho e os dados, mas muda a sequência de bytes. Portanto, essas duas conferências não comprovam que o arquivo seja uma cópia exata.

Atividade 2: recupere a mensagem

Execute o código para ver a mensagem preparada para envio em base64. Depois, altere a linha de mensagem_recuperada para que a saída volte a mostrar o texto original, com seus acentos. Use Validar solução para conferir o resultado.

import base64

mensagem_original = "falha de comunicação"
mensagem_em_bytes = mensagem_original.encode("utf-8")
mensagem_em_base64 = base64.b64encode(mensagem_em_bytes).decode("utf-8")
mensagem_recuperada = mensagem_em_base64

print(mensagem_recuperada)
Conferir resposta

Desfazer a base64 recupera os bytes da mensagem. Se a saída aparecer com b'...' e sequências como \xc3\xa7, o conteúdo já foi recuperado, mas ainda está sendo exibido como bytes. Interpretar essa sequência em UTF-8 devolve o texto legível, incluindo os acentos.

O que aprendemos

  • Unicode identifica caracteres por pontos de código. UTF-8 os codifica em bytes, e um caractere pode ocupar mais de um byte.
  • Hexadecimal e base64 representam bytes como texto e permitem recuperá-los. Não oferecem sigilo nem verificam alterações.
  • Importar e reexportar um JSON pode preservar os dados e mudar os bytes. Uma cópia exata precisa preservar todos os bytes do original.
