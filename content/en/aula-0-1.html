Guiding question

What must match for two files to be exact copies?

1. The record and the file

Digital records help document what was done. A test result, for example, can be presented as evidence in an audit. To assess that evidence, we also need to consider where the record came from and what happened to it before it reached us.

The auditor receives this record in a JSON file generated by a device. Before reaching the auditor, however, the file passed through another application, which imported the data and exported it again. It may have preserved every value while changing the field order and spacing. The auditor needs to distinguish an exact copy of the original file from a new representation of the same data.

Suppose the device generated this record in JSON, a text format that organizes data into fields and values. The field names mean record, device, timestamp and result; falha de comunicação means “communication failure”. These strings are kept unchanged in the examples so that their bytes remain the same:

{
  "registro": "T-0142",
  "equipamento": "EQ-17",
  "instante": "2026-09-10T14:30:00-03:00",
  "resultado": "falha de comunicação"
}

To recover these fields, the application reads a sequence of bytes stored in the file. Each byte consists of eight bits, each of which can be 0 or 1, allowing 256 different values. An encoding defines how text is written as this sequence. The record values, quotation marks, spaces and line breaks all need to be encoded.

In Python, the str type represents Unicode text. Unicode assigns numeric codes to characters: e is assigned 101, and é is assigned 233. These identifiers are called code points. UTF-8 defines how to represent them as bytes. The encode("utf-8") operation produces these bytes; decode("utf-8") recovers the text.

data = "é".encode("utf-8")
print(data)
print(data.decode("utf-8"))

A character can take up more than one byte. The word café, for example, has four characters but takes up five bytes in UTF-8: é takes two. Counting letters and spaces on the screen is therefore not the same as measuring the file size.

2. Hexadecimal and base64

To examine the bytes in the file, we can write them in hexadecimal: two digits per byte, using 0-9 and a-f. The five bytes of café become 63 61 66 c3 a9. The pairs c3 a9 correspond to é.

Base64 also lets us carry bytes in text fields. In this representation, the same five bytes become Y2Fmw6k=. Decoding the hexadecimal 636166c3a9 or this base64 recovers the same sequence. Neither form prevents the content from being read or checks whether it has changed.

import base64

data = "café".encode("utf-8")
hexadecimal = data.hex()
base64_text = base64.b64encode(data).decode("utf-8")

print(hexadecimal, bytes.fromhex(hexadecimal).decode("utf-8"), sep="\t")
print(base64_text, base64.b64decode(base64_text).decode("utf-8"), sep="\t")

3. The same data, different bytes

When importing the record, the application recovers the JSON fields and values. When exporting them, it produces new text, which may have different formatting. This transformation is a form of serialization.

Accents can also have different representations. Unicode allows é to be written as a single code point or as e followed by a combining acute accent. The two forms can look the same on screen and produce different bytes. Unicode normalization lets us convert them to a common form.

Re-exporting can change just the formatting or also alter the recorded values. The received file alone does not reveal what changed. To check whether it has been preserved, the auditor needs a reference from the original record.

Activity 2: recover the message

Run the code to see the message prepared for sending in base64. Then change the recovered_message line so that the output shows the original text again, including its accents. Use Validate solution to check the result.

import base64

original_message = "falha de comunicação"
message_bytes = original_message.encode("utf-8")
base64_message = base64.b64encode(message_bytes).decode("utf-8")
recovered_message = base64_message

print(recovered_message)
Check answer

Decoding the base64 recovers the message bytes. If the output appears with b'...' and sequences such as \xc3\xa7, the content has been recovered but is still being displayed as bytes. Interpreting this sequence as UTF-8 returns readable text, including the accents.

What we learned

  • Unicode identifies characters by code points. UTF-8 encodes them as bytes, and a character can take up more than one byte.
  • Hexadecimal and base64 represent bytes as text and allow them to be recovered. They do not provide secrecy or check for changes.
  • Importing and re-exporting JSON can preserve the data while changing the bytes. An exact copy must preserve every byte of the original.
