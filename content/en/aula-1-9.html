Objectives
  1. Create metadata from a Python dictionary.
  2. Observe its CBOR representation and hash.
  3. Explain how the transaction body is linked to these data.
Before you begin

Review hash calculations in Lesson 0.2 and the transaction's CBOR representation in Lesson 1.6.

Guiding question

If someone changes a message attached to a transaction, what happens to the hash of those data?

1. A message in the transaction

Metadata are optional data that can accompany a transaction, such as a message. Writing a message does not create tokens or make the network check whether the text is true.

In Python, we can represent these data with a dictionary: {1001: {"mensagem": "Olá, Cardano!"}}. The outer key must be an integer; we chose 1001 for this example. The person preparing the data chooses the key mensagem (Portuguese for “message”) and its text. We keep the original message, “Hello, Cardano!” in Portuguese, unchanged so that its bytes and hash remain the same.

2. Create metadata with PyCardano

Metadata takes the dictionary. The AlonzoMetadata and AuxiliaryData classes assemble the attachment in the format used by the transaction. Run the example: it shows the message, the attachment as hex-encoded CBOR and the attachment's hash.

from pycardano import Metadata, AlonzoMetadata, AuxiliaryData

message = "Olá, Cardano!"
data = Metadata({1001: {"mensagem": message}})
attachment = AuxiliaryData(AlonzoMetadata(metadata=data))

print("message:", data[1001]["mensagem"])
print("CBOR:", attachment.to_cbor_hex())
print("hash:", attachment.hash().payload.hex())

Use short messages: each metadata text string can occupy up to 64 bytes. Characters such as á take more than one byte in UTF-8.

Activity: change the message

Run the code above. Replace Olá, Cardano! with Olá, Ada! (“Hello, Ada!”) and run it again. What changed in the CBOR and the hash?

Then restore the original message and run it once more. Compare the result with the first run.

Check answer

Changing the message changes the attachment's bytes and its hash. When you restore the original message, the same code produces the original CBOR and hash again. The calculation depends on the data, not on when it runs.

3. How these data are linked to the transaction

The attachment sits in the auxiliary data, outside the transaction body. The body stores the attachment's hash in the auxiliary_data_hash field.

If the message changes, this field must be updated. That changes the body and its body hash. A transaction that has already been signed therefore needs new signatures after this change.

When the transaction is published, the message becomes accessible along with the other data.

What we learned

  • A Python dictionary can supply the data to create metadata with PyCardano.
  • Changing the message changes the attachment's CBOR and hash.
  • The auxiliary_data_hash field links the transaction body to the attachment.
